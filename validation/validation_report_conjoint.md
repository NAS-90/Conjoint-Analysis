# Validation – Conjoint Customer-Weighted View (demo)

## Setup

- Dataset: `outputs/conjoint_demo` (conjoint demo, generated by `scripts/build_demo_workbook.py`)
- Pipeline exercised:
  - `preprocessing.py` → `preprocessed_output.csv` + `attribute_column_map.json` (7 conjoint attributes, one-hot encoded)
  - `scripts/build_demo_importance.py` → `importance.csv` (re-uses the **real** published N=381 study weights)
  - `compute_distance_matrix.py` (technical) → `distance_matrix.csv`, `nearest_neighbors.csv`
  - `compute_distance_matrix.py --mode weighted` → `distance_matrix_weighted.csv`, `nearest_neighbors_weighted.csv`
- Configurations: 12 tractor specs covering every level of all 7 attributes.

## Conclusion

- 5 of the 12 configurations have a different top-3 nearest-neighbour ordering between the technical and customer-weighted views (including 4 of the 4 sampled above), confirming the weighting changes the results.
- Relative importances reproduce the published N=381 study, so the customer-weighted view is driven by authentic conjoint weights.
- The weighted distance matrix passes the same validity checks (square, symmetric, zero diagonal, finite) enforced by `compute_distance_matrix.sanity_checks`.
