First, the basics · 60 seconds

From a messy spreadsheet to "which products are alike"

  • 1A messy Excel goes in. Prices like "₹54,999", ranges like "61–70", Yes/No text — all mixed together.
  • 2A "data tidier" cleans it up into plain numbers a computer can compare.
  • 3Math measures the gaps. Products with small gaps are alike — likely competitors.

Everything depends on step 2. That's the part this update rebuilt.

01
The Problem · Repeated work

The same work, written three times

Three teammates had each written their own near-identical "data tidier". Three files doing basically the same job:

tidier #1
~90 lines

the generic one

tidier #2
~115 lines

a copy, for phones

tidier #3
~99 lines

another copy

Want to change one rule? You had to fix it in three places — and hope you didn't miss one.

02
The Problem · Too rigid

The rules were welded into the code

Picture a machine that only accepts one exact form. Feed it tractors — fine. Feed it phones — it jams, because the product name now sits in a different column.

  • Type Numeric with a capital N → works. Lowercase numeric → the whole column was silently dropped.
  • A new product category meant editing the program — i.e. waiting for a coder.

That directly breaks the project's #1 promise: "works for any product."

03
The Problem · Nobody else could run it

One chef, no recipe

The "dish" only worked when the original cook made it — no ingredient list, no recipe card. A new teammate was stuck at step zero.

  • No list of what to install → "but it works on my machine"
  • No setup guide → onboarding happened by word of mouth
  • Result files piled up loose and got overwritten every run

This is the P1 task "get the tool running for everyone" — and it wasn't met yet.

The fix, in one idea

Let the program
read a form —
not be rewritten.

You describe each column once, right in the spreadsheet. The code reads those notes and adapts itself to any product — no programmer needed.
